`verify-live-tokens.py` reports `TOKEN-EXTRA` as a *hint*: "the live sheet's leading chromatic
colour is absent from the spec". One note conflates an axis artefact (a vendor bundle, a
framework default, a rebuilt skin, a social row) with a real prep defect. This axis adjudicates

colour (`background` on a section vs `border` on a pseudo-element).

## What the fixer wrote

**239** specs (`MISSING-BRAND` + `DOC-ONLY`) get one measured row, labelled by the property
that paints the colour (`237` in the first pass, `2` found by the post-fix re-run and closed in
the follow-up: `dunkly`, `swish` — the cascade winner changed once a sibling row existed):

| label | property |
| --- | --- |
| `Surface (measured)` | `background` / `background-color` |
| `Accent (measured)` | `color` |
| `Token (measured)` | a custom property (`--brand`) |
| `Colour (measured)` | anything else |

**Never `Brand`.** A brand row would manufacture a claim for the brand-coverage axis, which
compares claims with what the shipped app paints, and would report a wave of UNSHIPPED apps
without any app changing. The row is a statement about the *reference*, not about the app:

* **8** of the 239 colours are painted by the shipped app (corroborated),
* **139** apps paint the palette their prep stated instead — the app is not wrong, the record
  was incomplete,
* **90** preps have no app at all (prep history for a design that shipped under another name).

Idempotent: a second run reports `already-stated` for every row and writes nothing, and the
axis converges — re-running it at the fix commit leaves `MISSING-BRAND 0`, `DOC-ONLY 0`
(1,004 → 780 subjects). 42 of these specs had no `## Design tokens` section at all — it is
created before `## Requirements`.

## Guards (each closes a measured false-positive class)

1. **Vendor bundles are not the design.** `gijgo.css` (a datepicker) led `autodock` with Material blue `#2196f3`; `/plugins/`, `/vendors/`, `libs/`, `bower_components/` and a name list (bootstrap, icon fonts, sliders, pickers, players) are vendor. The `bootstrap-sidebar` family is exempt — there the kit's `bootstrap.css` *is* the sheet.
2. **Social palettes are per-network.** `footer ul li:nth-child(3|4|5) a` paints three different colours (Pinterest/Twitter/Facebook): a family with >=3 distinct chromatic colours, or a `share|social` selector, is excluded from the census.
3. **`.active` is a state.** `#f16947`'s only sites on the accordion family were `.cl-item.active .cl-btn-link` — a selected-item state, not a surface.
4. **Pseudo-elements are markers.** `li:before` / `::after` backgrounds paint bullets, arrows and underlines.
5. **Chrome is not a surface.** Progress fills (`count-bar`, `skill-bar`), loaders, dividers, scrollbars are decor — `zenflow`'s `#239191` came from `.count-bar .color-1 .count`.
6. **Framework defaults are never a brand** (`#007bff`, `#0d6efd`, `#0275d8`, `#0044cc` and ~35 more).
7. **A rebuilt skin is drift** (`?v=3.x`, `css/kit/`) — the same rule as `verify-shape-tokens.py`; a plain `style.min.css` is *not* drift, only the versioned query is.
8. **Cascade order decides.** A kit default re-declared by the theme's own sheet is not the colour the browser paints: `cascade_winner()` reads the LAST `(selector, property)` in link order, and when the winner is already in the spec the spec was right (`EFFECTIVE-STATED`, 6).
9. **A shared sheet is not this design's palette.** The same `(sheet sha, colour)` in >=3 preps is a component kit (`SKELETON`, 105).
10. **One-off accents are not surfaces.** Fewer than 3 declarations on a non-section, non-CTA selector is `WEAK`.
11. **A gradient stop is decorative** unless the selector is a page section (`hero|banner|section|nav|footer|…`).
12. **Comments are not paint** — `strip_comments()` runs before both the census and the site parse.
