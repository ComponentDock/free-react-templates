# App-side fidelity delta — does each app paint the measured brand?

```sh
python3 scripts/verify-app-fidelity.py --md docs/app-fidelity-delta.md
python3 scripts/verify-app-fidelity-controls.py   # 29/29
```

Generated by `scripts/verify-app-fidelity.py` (offline, read-only; it
never edits `apps/`). Every other token axis compares a spec against
its live reference sheet. This one compares the shipped app's own
palette against the brand-role colours its prep measured.

_Provenance: sheet-claims pass, 2026-10-23 — 25 rows proved `declared only by` a block the page never renders (EVIDENCE-SHEET-ONLY): UNSHIPPED 135 claims / 115 apps -> 110 / 96. Residual: 82 RENDERED app debt, 23 NOT-IN-SHEET re-measure, 2 VAR/UNKNOWN, 3 UNVERIFIED (docs/app-fidelity-sheet-only.md)._

Corpus: **3229** specs, **1703** of them
with a shipped app (`apps/<name>/src`), **2165** brand-role
colour claims evaluated.

## Method

* **Claim side** — the brand-role rows/bullets of
  `openspec/specs/template-<name>/spec.md` whose role label contains
  `brand|primary|accent|cta|secondary` (variant labels such as `hover`,
  `scale`, `tint` excluded; evidence fences, sibling sentences,
  re-valuation arrows and rebuilt-sheet drift notes skipped).
* **Claim scope** — a row can disqualify itself in its own words,
  measured on 2026-10-23: a framework's own default (`stock BS5
  --bs-primary in the vendor block (not the design)`), a base rule the
  final one overrides (`fully overridden … do NOT reproduce`), an
  explicitly `unused standalone` gradient stop, a diagnostic state
  (`loader`, `.alert-box--error`, `[aria-invalid]`), and a debt the
  prep already adjudicated (`recorded as a deliberate …`). Those are
  notes, never flags: the app is right to omit them. So is a row that
  states alternatives (`#a` / `#b`) when the app paints either member,
  and a row whose block the reference page never renders (`declared
  only by .genric-btn.info … block absent from the page markup`) —
  measured by `scripts/verify-sheet-claims.py`, see
  `docs/app-fidelity-sheet-only.md`.
* **App side** — every hex in `apps/<name>/src/**` (`.css`, `.tsx`,
  `.ts`, `.html`), matched in hex or `rgb()/rgba()` notation.
* **UNSHIPPED** — a measured brand colour with no counterpart in the
  app, nearest app chromatic more than **24** RGB units away (max
  channel). Closer neighbours are `APPROX` notes: the app paints a
  drift, not a different colour.
* **UNDOCUMENTED-ANCHOR** — `--color-brand` / `--color-accent` /
  `--color-secondary` holds a hex no spec token states and no spec hex
  is within 24 units of: the app invented a brand colour.
* An app whose `src` holds **no chromatic hex** (Tailwind named-palette
  utilities only) is `NO-TOKEN`: not comparable from source, not a
  defect. A spec with no brand-role colour is `NO-CLAIM`. Alias preps
  (`prep-status: shipped-as=`) are out of scope.

## Reading the numbers

Severity is the max-channel distance between the measured colour and
the closest the app paints:

| Δ | claims | what it means |
| --- | --- | --- |
| 25–49 | 28 | a re-picked shade of the same hue |
| 50–89 | 35 | a neighbouring colour family |
| 90+ | 47 | a different colour: the design's accent was replaced |

A colour that recurs across apps is one shortcut, not N mistakes: the
most repeated here is `#4f46e5` (4 apps), and each app replaced
it with a hue of its own choosing.

## What to do with a hit

* The app is the defect: restyle it to the measured hex (implementer
  stream, normal PR) — never edit `apps/` from the prep clone.
* The app is right and the prep was wrong: record the decision in the
  spec (`post-ship delta` line naming both values) so the next audit
  reads it as adjudicated, not as drift.
* An `APPROX` row needs no change: it records how far the app's hue
  sits from the measured one.
* A row listed under **Claims dismissed by their own evidence** needs
  no change either: its text already says the colour is the vendor's,
  unused, a state, an alternative the app ships, or a decision the
  prep recorded. Re-open it only if the row's *text* is wrong.
